Building the E-Tongue: Bridging Ayurveda & Electronics

The concept of Rasa (taste) in Ayurveda is fundamental to determining a herb's medicinal properties. For thousands of years, this has been an incredibly subjective process, reliant on human experts. Our goal with the E-Tongue project was ambitious: to digitize taste and create an objective, electronic system capable of identifying and classifying Ayurvedic herbs.

The Hardware Stack

At the core of the E-Tongue is a multi-sensor chemical array. Human taste buds work by detecting specific ions and molecules; we replicated this using ion-selective electrodes (ISEs) and lipid polymer membranes. These sensors are incredibly sensitive to changes in voltage caused by the presence of specific ions.

  • Sweet (Madhura): Detected via carbohydrate-sensitive membranes.
  • Sour (Amla): Measured using highly precise pH sensors.
  • Salty (Lavana): Detected using sodium/potassium ion-selective electrodes.
  • Bitter (Tikta) & Pungent (Katu): Measured using specific alkaloid-sensitive membranes.

These analog signals are minuscule—often in the millivolt range. To process them, we used an instrumentation amplifier array before feeding the signals into the Arduino's 10-bit ADC. The Arduino acts as the primary data acquisition unit, rapidly sampling the sensor array and applying basic digital filtering to remove noise.

Signal Processing & Fingerprinting

Raw voltage data isn't enough. Every herb creates a unique response curve across the sensor array over time. We programmed the Arduino to capture these transient responses and transmit them via Serial to a host computer. Here, we apply Principal Component Analysis (PCA) to reduce the dimensionality of the data, creating a unique "taste fingerprint" for each herb.

Once we have a fingerprint, we can compare it against a database of known, authenticated Ayurvedic herbs. This allows us to instantly verify the authenticity of a sample and detect adulteration with high accuracy.

Future Scope

While the current prototype uses an Arduino, we are planning to upgrade the processing core to an STM32 for its superior 12-bit ADCs and real-time DSP capabilities. Coupled with an ESP32, the E-Tongue will soon be a fully wireless, cloud-connected IoT device capable of pushing taste fingerprints directly to an AI model for advanced neural network classification.

Bridging the gap between ancient Ayurvedic wisdom and modern embedded systems has been an incredible engineering challenge, and we're just getting started.

How They Work Together

The STM32 + ESP32 combined system is a powerful dual-processor embedded architecture where each chip handles what it does best. The STM32 acts as the real-time processing core — managing sensors, motors, PWM, ADC, and timing-critical tasks with microsecond precision. The ESP32 acts as the communications brain — handling WiFi, Bluetooth, MQTT, HTTP, and cloud connectivity.

Together they communicate via UART, SPI, or I2C, with the STM32 sending processed data or commands to the ESP32, which then relays it to the cloud, a mobile app, or a web dashboard — all in real time.

This architecture is already used in industrial IoT gateways, smart robotics, automotive ECUs, medical devices, and smart agriculture systems. On a unified PCB, this eliminates external wiring, reduces latency, and shrinks the form factor significantly.

03 // Interface Protocols

Communication Between STM32 & ESP32

UART — Most Common Method

UART (Universal Asynchronous Receiver Transmitter) is the simplest and most reliable way to connect STM32 and ESP32. Only 2 wires needed (TX/RX), no clock line required. Supports up to 4 Mbps baud rate.

The STM32 sends JSON or binary frames over UART. ESP32 receives them, parses the data, and forwards to WiFi/cloud. Replies from cloud travel back the same way.

// STM32 UART Transmit
HAL_UART_Transmit(&huart1,
  (uint8_t*)data, len, 100);

// ESP32 Receive
Serial1.begin(115200);
if(Serial1.available()){
  String msg = Serial1.readString();
}

SPI — High Speed Transfer

SPI (Serial Peripheral Interface) offers much higher speeds than UART (up to 80 MHz on ESP32 slave). Uses 4 wires: MOSI, MISO, CLK, CS. STM32 acts as Master, ESP32 as Slave. Ideal for transferring large data buffers — images, audio frames, large telemetry packets.

STM32 (Master) → MOSI → ESP32 (Slave)
STM32 (Master) ← MISO ← ESP32 (Slave)
STM32 → SCK → ESP32
STM32 → CS (GPIO) → ESP32 CS pin

// Max speed: 10 MHz typical, 40 MHz max
SPI.begin(SCK, MISO, MOSI, CS);
SPI.setFrequency(10000000);

I2C — Multi-Device Bus

I2C uses only 2 wires (SDA + SCL) and supports up to 127 devices on one bus. Both STM32 and ESP32 can act as I2C master or slave. Useful when the board also has sensors (BME280, MPU6050, SSD1306) all sharing the same bus.

// STM32 I2C Master write to ESP32 (addr 0x50)
HAL_I2C_Master_Transmit(
  &hi2c1, 0x50<<1, data, len, HAL_MAX_DELAY);

// ESP32 as I2C Slave
Wire.begin(0x50, SDA_PIN, SCL_PIN);
Wire.onReceive(receiveEvent);

USB / OTG — Programming & Debug

On the combined ESTM32 board, USB-C connects to ESP32's built-in USB-UART bridge. This lets you program ESP32 directly and use it as a USB-to-UART bridge to program STM32 as well, reducing the number of USB ports needed on the final board.

USB-C → CP2102/CH340 (on ESP32 module)
→ ESP32 UART0 (GPIO1/GPIO3)
→ STM32 USART1 (PA9/PA10)

for STM32 programming mode entry

06 // Future Scope

Future Applications & Scope

The combination of STM32's real-time precision and ESP32's wireless versatility on a single board represents the direction embedded systems are heading. As IoT, edge AI, Industry 4.0, and autonomous systems grow, this dual-processor architecture becomes the standard for smart, connected, real-time devices.

Future iterations of combined STM32+ESP32 boards will include on-chip AI inference (TinyML via STM32's AI extension and ESP32-S3's vector instructions), 5G/LTE modules replacing ESP32's WiFi, and hardware security elements for industrial and medical certification. The form factor will shrink to System-on-Module (SoM) designs used in wearables, drones, and automotive ECUs.

Projects like the E-Tongue Ayurvedic Herb Testing System (developed by Rohan Bombale at Vidyalankar Polytechnic) demonstrate exactly this potential — STM32 handles precise sensor ADC readings from chemical sensor arrays while ESP32 transmits the taste fingerprint data to a cloud database and ML model for herb classification. This is precisely the future of embedded bioelectronics.
